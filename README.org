* 概览

这是一个以 *Vim 9 + Vim9script* 为核心的个人开发工作台。插件清单已经完全收敛到
=beamiter/simple*= 生态，同时把基础编辑能力、插件层、行为逻辑和键位层分开：

#+begin_example
.vimrc
└── config/
    ├── lib.vim        跨模块共享辅助（消息输出、statusline 段位注册）
    ├── core.vim       核心选项、undo/swap/state
    ├── bootstrap.vim  首次启动自动安装 SimplePlug 并接续 PlugUpdate
    ├── plugins.vim    插件配置与 SimplePlug 清单
    ├── behavior.vim   FileType、缩进规则、尾随空白与核心自动命令
    ├── compat.vim     插件兼容层（侧栏 statusline、补全 Enter）
    ├── health.vim     健康检查、可复制报告、模块加载耗时
    ├── workflow.vim   大文件保护、项目根目录、quickfix 工作流
    ├── search.vim     原生异步项目搜索、取消与 quickfix 结果隔离
    ├── remote.vim     SimpleRemote 控制器的热重载入口
    ├── workbench.vim  simple* 原生动作、只读上下文与集成诊断
    ├── mappings.vim   所有真实键位与 SimpleWhichKey 描述
    └── update.vim     配置仓库更新检查（只读 fetch，拉取需显式执行）
#+end_example

只需要链接一个 =~/.vimrc=。顶层配置会根据自身真实路径加载其他模块，因此仓库
不必固定放在 =~/vimrc=。

设计原则：

- 一次启动完成：SimplePlug 缺失时自动在后台获取最新主分支、构建并原子启用；
  成功后自动接续 =:PlugUpdate=，最后重载配置，让新插件在当前会话直接可用。
- 安装器离线、首次启动联网：=utils/install.sh= 默认只创建链接，不访问网络；
  真正的插件下载从用户第一次打开 Vim 后开始。语言服务器仍不会自动下载。
- 可降级：SimplePlug 或所有插件都不存在时，Vim 的核心编辑能力仍能正常启动。
- 可恢复：启用 swap、write-backup 和 persistent undo，状态统一放在 XDG state。
- 项目友好：自动读取 =.editorconfig=，并能从当前文件向上发现工作区根目录
  （=.git= / =Cargo.toml= / =CMakeLists.txt= / =compile_commands.json= 等）。
- 大文件可控：按字节数、行数和长行检测，支持手动开关；分屏各自保存并恢复显示选项。
- 离线也能工作：无插件时仍有项目根目录、异步 ripgrep 搜索和 quickfix 导航。
- 默认值可覆盖：=.vimrc.before= 中的插件设置、主题和图标选择在重载后继续生效。
- 单一键位来源：插件默认映射尽量关闭，真实 mapping 与 SimpleWhichKey 描述放在
  一起；没写描述的键位，面板直接从 mapping 的 rhs 里读。
- 可验证：提供空 HOME 离线回归、本机完整插件栈测试和 GitHub Actions 自动检查。

* 要求

** 运行时

- Vim 9.1 或更新版本。
- 必需特性：=+vim9script=、=+job=、=+channel=、=+timers=、
  =+popupwin=、=+textprop=、=+persistent_undo=。
- Git：插件安装、更新及 SimpleGit。
- ripgrep (=rg=)：原生 =:VimrcGrep= 搜索；未安装时其他核心编辑能力仍可使用。
- Bash 与可访问 GitHub 的网络：首次自动配置需要。
- Nerd Font 可选；当前 UI 默认使用 Nerd Font 图标。

执行 =:VimrcHealth= 可以检查当前环境；=:VimrcHealth!= 打开可搜索、复制的报告。

** 构建插件

部分 =simple*= 插件包含 Rust 后端。自动 bootstrap 会直接调用各仓库自己的
=install.sh=，因此需要：

- Bash
- Rust/Cargo 满足各插件 =Cargo.toml= 声明的最低版本
- 各插件安装脚本所需的系统开发库

不构建插件也不影响核心模式。

=./utils/deps.sh= 检查核心依赖；准备构建插件时使用
=./utils/deps.sh --build=，它会严格检查 Cargo 和 Rust 是否可运行。

* 安装

** 1. 链接配置（默认、这一步完全离线）

#+begin_src shell
./utils/install.sh
#+end_src

安装器会：

- 从脚本自身定位仓库；
- 安全备份已有 =~/.vimrc=；
- 创建绝对符号链接；
- 重复执行时保持幂等；
- 同一 HOME 的并发安装互斥，失败时恢复旧配置并保留外部新改动；
- 不调用 git、cargo、Vim、sudo 或包管理器。

预览操作而不写入：

#+begin_src shell
./utils/install.sh --dry-run
#+end_src

** 2. 打开 Vim，自动完成全部配置

#+begin_src shell
vim
#+end_src

首次启动会自动完成下面的单次流水线，无需退出、重开或输入命令：

#+begin_example
VimEnter
  → 后台 clone SimplePlug 最新默认分支
  → 在私有 staging 目录构建并验证 daemon
  → 原子启用 SimplePlug
  → 自动重载 vimrc
  → 自动 :PlugUpdate（安装其余插件并执行可信 hook）
  → 更新完成后再次重载，关闭进度窗并回到原编辑窗口
#+end_example

bootstrap 期间核心编辑能力已经可用。失败不会留下半成品，也不会退出 Vim；可用
=:VimrcBootstrapStatus= 查看最近日志，修复网络或 Rust 环境后执行
=:VimrcBootstrapRetry=。=:VimrcBootstrapStop= 可停止仍在运行的 bootstrap。
停止会同时终止这次下载或构建的子进程。目标级锁防止两个 Vim 同时替换管理器。

正常中断会释放锁。若进程被 =SIGKILL= 强制杀死，先确认对应安装/构建进程已结束，
再移除遗留的 =~/.vimrc.install.lock= 或插件目录下 =.simpleplug.bootstrap.lock=
后重试；安装器不会自动抢占一个可能仍在使用的锁。

** 3. 可选：同时安装全局 SimpleCC 配置入口

#+begin_src shell
./utils/install.sh --profile full
#+end_src

=full= 会额外把 =simplecc.json= 链接到：

#+begin_example
${XDG_CONFIG_HOME:-$HOME/.config}/simplecc/simplecc.json
#+end_example

=.vimrc= 会显式指定这个用户级配置；未安装 =full= 时则显式使用仓库内的
=simplecc.json=。项目中的 =simplecc.json= 默认不会被自动读取。

** 4. 可选：在打开 Vim 前预先安装 SimplePlug

通常不需要这一步；若希望先在 shell 中完成管理器构建，可执行：

#+begin_src shell
./utils/install.sh --bootstrap-simpleplug
#+end_src

该选项获取远端当前默认分支，在私有 staging 目录完成构建和验证后才替换管理器；
已有目录会保存在 =.vimrc-bootstrap-backups/=。随后只需打开 Vim，SimplePlug
会自动补装其余缺失插件。

日常检查和完整更新仍可显式执行：

#+begin_example
:PlugStatus
:PlugUpdate
#+end_example

* 配置自身的更新检查

启动完成后（=VimEnter= 之后约 0.8 秒）会异步执行一次
=git fetch --quiet --no-tags=，然后比较本地 =HEAD= 与 upstream。落后时提示：

#+begin_example
[vimrc] 配置落后 origin/master 3 个提交，运行 :VimrcUpdate 拉取
#+end_example

fetch 在后台 job 中进行，不阻塞启动；超时后 job 会被终止。检查结果保存在
=g:vimrc_update_status=（=upstream= / =ahead= / =behind= / =checked=）。节流时间
戳文件在 =${XDG_STATE_HOME:-$HOME/.local/state}/vim/update-check=。

同一份状态还会渲染到 statusline 上：落后时 SimpleLine 右侧出现
=󰚰 3=（=SimpleLineDiagWarn= 高亮），已是最新则不占位置。实现是 SimpleLine 的
用户段位接口 =g:simpleline_custom_right=，=config/update.vim= 注册
=g:VimrcUpdateStatusline= 进去；该函数只读 =g:vimrc_update_status=，不会在重画
时跑 git。SimpleLine 版本过旧（没有这个接口）时段位不显示，其余功能不受影响。

| 命令 | 功能 |
|-
| =:VimrcUpdateCheck= | 忽略节流，立刻检查一次并汇报结果 |
| =:VimrcUpdate= | =git pull --ff-only=；工作区有未提交改动时拒绝执行 |
| =:VimrcReload= | 先停止更新检查 job、断开 SimpleRemote，再重新 source =~/.vimrc= |

对应键位：=<leader>vc= 检查，=<leader>vu= 更新，=<leader>vr= 重载。

可调项（放在 =~/.vimrc.local=）：

#+begin_src vim
let g:vimrc_update_check = 0        " 完全关闭自动检查
let g:vimrc_update_interval = 3600  " 自动检查最小间隔（秒），默认 86400
let g:vimrc_update_delay = 2000     " 启动后延迟多久 fetch（毫秒），默认 800
let g:vimrc_update_timeout = 10000  " fetch 超时（毫秒），默认 20000
#+end_src

环境变量 =VIMRC_SKIP_UPDATE_CHECK=1= 等价于关闭自动检查；=utils/check.sh= 会
自动设置它，测试始终不联网。

自动检查只覆盖配置仓库。插件首次配置会自动执行一次完整 =:PlugUpdate=；以后
新增但缺失的插件会由 SimplePlug 自动补装，已有插件的日常完整更新仍由
=:PlugUpdate= 显式触发。

=:VimrcUpdateStop= 取消当前 fetch/pull 及待启动的定时检查。fetch 和 pull 互斥；
网络操作不会弹出凭据输入，失败会显示原因。fetch 默认 20 秒超时，pull 默认
120 秒超时（=g:vimrc_update_pull_timeout=，毫秒）。工作区状态读取失败或存在
未提交改动时，=:VimrcUpdate= 会停止，成功时仍只允许 =--ff-only=。

重复 =:source= 或 =:VimrcReload= 会取消这些任务；异步控制器保留函数生命周期，
旧任务的退出和输出不会污染新任务。修改 =bootstrap.vim=、=search.vim= 或
=update.vim= 控制器代码后需要重启 Vim，普通配置和键位仍可直接重载。

* 安全与状态

Vim 状态默认写入：

#+begin_example
${XDG_STATE_HOME:-$HOME/.local/state}/vim/
├── undo/
├── swap/
├── backup/
├── session/
└── viminfo
#+end_example

- =undofile=：跨会话撤销。
- =swapfile=：崩溃恢复。
- =writebackup=：写入过程中保留临时保护副本。
- =nobackup=：成功写入后不长期保留 =~= 文件。
- =viminfo=：marks、registers、命令历史和 oldfiles。
- SimpleStartify session 只存放在权限受控的 state 目录。
- 如果 state 目录无法创建或写入，undo、swap 和 write-backup 会关闭，不会退回到
  项目目录生成恢复文件。
- 无效或指向根目录的 XDG 路径会被忽略；无效的 =HOME= 会直接停止加载，避免向
  当前目录或文件系统根目录写状态。

配置默认设置：

#+begin_example
g:simpleplug_auto_install = 1
g:simplecc_auto_install = 0
#+end_example

因此新增插件会自动补齐，但语言服务器仍通过 =:SimpleCCInstall= 按需安装。
SimpleCC 配置中的 =command= / =args= 会启动本地进程，因此默认只信任这个仓库或
用户级 XDG 配置，不自动信任刚打开项目里的配置。

若需要完全离线启动，可在 =~/.vimrc.before= 中关闭两层自动化：

#+begin_src vim
vim9script
g:vimrc_simpleplug_auto_bootstrap = 0
g:simpleplug_auto_install = 0
#+end_src

一次性环境变量 =VIMRC_SKIP_SIMPLEPLUG_BOOTSTRAP=1= 只关闭管理器 bootstrap；
=VIMRC_SKIP_PLUGINS=1= 会跳过整个插件层。首次更新等待上限默认一小时，可通过
=g:vimrc_simpleplug_update_timeout= 调整（秒）。

需要在插件加载 *之前* 生效的机器设置放在 =~/.vimrc.before=，例如 leader、插件
目录和 =g:simple*= 选项：

#+begin_src vim
vim9script
g:vimrc_plugin_home = '/data/vim/plugged'
g:simplecc_semantic_tokens = 1
g:simplefinder_max_results = 600
g:simpletree_width = 32
g:vimrc_colorscheme = 'habamax'
g:vimrc_background = 'dark'
#+end_src

普通机器专属设置放在 =~/.vimrc.local=，它在所有共享模块之后加载，例如：

#+begin_src vim
vim9script
set ambiwidth=double
#+end_src

两个文件都可选且不进入版本控制。可调的核心开关：

#+begin_src vim
g:simpleeditorconfig_enable = 0   # 关闭本地/远端 EditorConfig
g:simpleedit_yank_highlight = 0   # 不高亮刚复制的文本
g:vimrc_large_file_bytes = 0      # 关闭自动大文件检测，仍可手动 on
g:vimrc_root_markers = ['.git']   # 自定义项目根标记
g:vimrc_whitespace_highlight = 0  # 关闭尾随空白提示
#+end_src

在 Anvil、Ember、Forge、Frost 的 Vim9 IDE 中，普通文件窗口自动使用
=nowrap nospell nolist conceallevel=0 foldcolumn=0 nofoldenable= 和单列
=signcolumn=yes=，让长行、诊断标记和滚动保持原生绘制。FileType、分屏、窗口切换
和 =:VimrcReload= 后会重新应用；普通终端 Vim 的换行、提交信息拼写检查和双列
signcolumn 偏好不变。已连接的 SimpleRemote 虚拟文件也使用相同视图，缓冲区的
URI、连接 generation 必须与当前工作区一致；断线、过期连接及其他 acwrite
缓冲区保留各自配置。设置 =g:vimrc_native_remote_view = 0= 可关闭远端视图同步。
diff 和插件窗口仍保留自身显示与折叠；RTL 不会被自动关闭。

IDE 默认关闭 SimpleCC 的自动 inlay hints 与签名弹窗，保留补全、诊断、Git signs
及手动 hover/minimap 等命令。若需要提示，可在 =~/.vimrc.before= 显式设置
=g:simplecc_inlay_hints = 1= 或 =g:simplecc_signature_help = 1=；此类用户设置在
重载后仍然生效。更新后的四终端可原生绘制不换行视图中的单行 inline hints，
以及 CodeLens 和诊断的单行行末文字；复杂布局仍由 Vim 兼容视图显示。
下文的原生文字浮层可用于手动 hover、
签名提示和 Git hunk 预览。

** 四终端与 simple* 的共同工作台

Anvil / Forge / Ember / Frost 的原生命令面板现在能直接调用这份配置里的
=simple*= 工作流。在更新共享核心与终端后，打开 =Ctrl+Shift+P=，输入 =>simple=
可以发现文件查找、实时 grep、outline、重命名、代码动作、Git、Markdown 和键位提示；
也可以用 =>git=、=>markdown= 等词缩小范围。选择之后执行的仍是对应的 SimpleFinder、
SimpleCC、SimpleGit 或 SimpleMarkdown 命令，现有 =Space= leader 键位继续有效。

面板打开时会读取当前窗口的工作区、Git 分支/变更数、SimpleCC 诊断数和
SimpleRemote 连接。普通编辑时不额外开启工具栏或侧栏。诊断数量来自插件已发布的
buffer 缓存，不会为了显示数字改写 quickfix、请求 LSP 或启动 Git 进程。
=g:VimrcWorkbenchDiagnostics()= 只读取已加载 SimpleCC 的诊断快照，最多 256 条，
返回当前 buffer 的 1-based UTF-8 字节位置，不修改 quickfix 或请求语言服务。
提供者尚未报告时数字也是零；它不代表已经完成一次诊断或 Git 检查。

buffer 或对应命令缺失时不提供。工作区符号实时搜索保留 SimpleCC 的 Vim
兼容交互视图，输入查询后使用上下键选择、Enter 跳转、Esc 关闭；签名帮助
使用已接入的原生文本 popup（不支持的布局仍回退到 Vim 兼容视图）。这些入口
复用现有快捷键，也能在四终端命令面板或 =:VimrcAction {id}= 中调用。

树动作仅在实际提供者可用时出现。单独安装远程包装器但缺少 SimpleTree 时，
只在已连接的虚拟远程工作区提供树；定位动作还要求当前为有远程路径的 buffer。
终端会话由 SimpleTerminal 管理，F8 收起后再次打开会复用现有 shell。
Visual 模式的 =Space tx= 发送当前活动选区覆盖的行，支持反向及连续选择，
不依赖上次退出 Visual 时留下的标记。

=simple_rename= 打开 SimpleCC 自己的 Vim 重命名提示，保留插件的交互和确认流程；
它与携带新名称的原生 typed rename 请求分别处理。插件窗口、大文件保护或只读
buffer 会限制不适用的语义/编辑动作。菜单显示后如果上下文改变，执行时会再次
检查可用性。Markdown 文档预览、WhichKey 等窗口继续使用插件自身 UI；不支持的
绘制仍按终端已有策略回退。SimpleCC 与 SimpleGit 的文字浮层按下文接入原生绘制。

*** 原生文字浮层：现有 simple* 动作直接受益

更新 SimpleCC、SimpleGit 以及四终端后，render protocol 6 可以在原生编辑区上
绘制它们声明支持的矩形文字浮层。内容、位置、关闭时机及按键仍由 Vim/插件管理，
终端直接绘制 GUI RGB 颜色、语法文字、边框和留白。短且完整可见的 hover、签名、
当前行诊断、补全文档、Git hunk 和 blame 因而无需切换整个编辑区的绘制方式。
补全列表与说明文档可以同时存在，按 Vim 的层级覆盖跨分屏区域。

| 体验入口 | 内容来源 |
|-
| =Space lh= / =:SimpleCCHover= | LSP 悬浮文档 |
| =Space ls= / =:SimpleCCSignatureHelp= | 函数签名及参数说明 |
| =:SimpleCCDiag= | 当前行诊断详情 |
| 补全列表中的文档 | SimpleCC 已有的补全/resolve 流程 |
| =Space gp= / =:SimpleGitHunkPreview= | 当前 hunk 的 diff 语法高亮 |
| =:SimpleGitBlameLine= | 当前行 blame 文字弹窗 |

浮层出现时暂停原生像素滚动和源坐标鼠标请求，让事件回到 Vim；浮层消失后恢复。
插件保留原有 =moved= / =close= 行为，浮层文字不进入 buffer 的可编辑坐标映射。
未声明支持、需要实际换行/滚动/裁剪、带交互 filter、标题或透明遮罩的弹窗
继续使用兼容显示。Vim 无法完整查询遮罩，因此只接受插件明确声明的无遮罩
文字浮层，避免把不透明矩形错误盖在其他 UI 上。

=Space vw= 的 =Popups= 一行显示当前已认证桥接是否支持该协议。旧终端和普通
Vim 仍使用原有弹窗。自动 inlay hints、自动签名提示及侧栏默认值保持现有配置。
Markdown 动作同时尊重 =g:simplemarkdown_filetypes=，包括 Pandoc、Rmd、VimWiki、
GitHub Markdown、自定义类型和显式空列表；无 filetype 的 =remote://= Markdown
buffer 也可通过文件扩展名识别。此入口调整不等于新增富文本 Markdown 渲染器。

*** 原生行内／行末提示与 CodeLens 身份校验

更新共享核心和四终端后，SimpleCC 的 =:SimpleCCCodeLens= 以及可选的行末诊断
可直接显示在原生编辑区。提示保留 GUI 高亮，按可见宽度截断，不改变 buffer 内容
或源文件的字节坐标。=Ctrl+Shift+P= → =>code lens= 可以刷新、执行；
=:VimrcAction simple_code_lens= 与 =simple_code_lens_run= 提供相同入口。
执行动作在只读、不可修改、受大文件保护及插件 scratch buffer 中不会被工作台调用。

=Space vw= 分别显示 =Virtual text= 和 =Inline hints= 状态。它们检查已认证连接与
桥发布的 =g:jterm_vim9_virtual_text_after=、=g:jterm_vim9_virtual_text_inline=，
不会把旧版 protocol 6 的弹窗支持误认作行末或行内提示支持。支持的 =nowrap=
视图可原生显示 SimpleCC 类型／参数提示，文字与 UTF-8 源文件字节坐标分开；
需要换行或改变行高等复杂布局继续使用 Vim 兼容绘制。

用户的 inlay 默认偏好保持不变。执行 =:VimrcAction simple_inlay_hints= 或
=Space ih= 可切换提示；再次执行即可关闭。关闭会清除其他已打开 buffer 的提示，
并取消未完成回复。SimpleCC 只缓存 Vim 成功放置的非空提示，因此无效的首条回复
不会阻止后续有效提示恢复；CJK、emoji 的 UTF-16 位置会转换为 Vim 的字节列，
并保留语言服务器提供的左右 padding。

CodeLens 的执行绑定到产生它的文档 URI、buffer、changedtick、filetype 和 daemon
代次；选择菜单打开后发生编辑、切文件或刷新提示，旧选择会被拒绝。daemon 再检查
请求 generation 与 URI，防止异步回包把相同 index 指向另一条命令。空结果会清除
旧提示，显示与清空都会通知原生界面。请同步更新并重新构建 SimpleCC daemon：
新版插件收到不带 generation 的旧回复时仍可展示提示，执行会提示重建 daemon。

普通 Vim 也能使用相同入口，无需四终端或任何插件：

#+begin_example
:VimrcWorkbench                 " 查看连接、上下文及当前可用动作
:VimrcAction simple_files       " 执行固定动作，Tab 只补全当前可用项
Space vw                       " 打开工作台报告，q 关闭
Space va                       " 输入 :VimrcAction ，继续 Tab 补全
Space Ps / Pc                  " 插件状态 / 检查插件更新
Space Pi / Pu / Px             " 安装缺失插件 / 更新 / 停止当前任务
Space Pd / Pp / Ph             " 审阅更新变化 / 启动耗时 / 管理器健康
Space vL / vS                  " 切换 SimpleLine / 查看状态栏健康
#+end_example

=Space P= 使用大写 P，保留现有小写 =Space p= Markdown 预览键位。
SimpleWhichKey 会把它显示为独立的 plugins 分组。工作台的状态现在还包括
SimpleCC 已发布的语言服务状态、SimpleTree 当前 tab 的显示状态与缓存根目录、
SimpleLine 是否启用，以及 SimplePlug 当前／上次操作的进度、安装数、更新数和错误数。
这些数是该次操作的结果，不是已安装插件总数；旧 SimplePlug 没有
=simpleplug#WorkbenchState()= 时明确显示状态未知。

安装、更新、状态查询和更新检查不会因为面板打开或读取状态而自动执行。
新版 SimplePlug 正在执行任务时，不提供冲突的第二个操作；只有实际运行时才出现
Stop。进度通过事件更新，取消任务后退出运行状态，迟到回复不能把取消结果改成成功。
Git 修改块入口要求已保存文件和该 buffer 的缓存；暂存／丢弃还要求可写且未进入
大文件保护，不会把未保存内容当成 Git 文件中的变更。现有直接 SimpleGit 键位保持原样。

没有插件时，报告仍然可用，其余动作等对应插件就绪后自动出现。报告只读、不触碰
源 buffer、寄存器或 quickfix。连接状态使用桥认证后的 =g:jterm_vim9_connected=，
单独继承地址、token 或旧 bridge-loaded 标记不会被显示为已连接。

需要禁用集成或某些动作时，在 =~/.vimrc.before= 中设置；重载会保留这些选择：

#+begin_src vim
g:vimrc_workbench_enable = 0
# 或只禁用指定动作：
g:vimrc_workbench_disabled_actions = ['simple_git_diff', 'simple_grep']
#+end_src

桥接 API 是 =g:VimrcWorkbenchCapabilities()=、=g:VimrcWorkbenchAction(id)= 和
=g:VimrcWorkbenchState()=。动作名来自固定清单，不接受任意 Ex、按键序列或 shell
文本；项目根目录仅在窗口/工作区事件中刷新，状态读取不会反复遍历目录。

** 编辑与配置边界

为防止刚打开的项目执行未信任配置，默认启用 =nomodeline= 和 =noexrc=。

* SimpleRemote：接近本地的远程工作区

SimpleRemote 已从 =config/remote.vim= 的单体实验代码重构为独立的
=beamiter/simpleremote= 插件，并由 SimplePlug 安装和更新。Vim 和所有 UI 始终运行在
本地，transport 支持 SSH host 与 Docker container；=:SimpleRemote= 会统一列出
profile、最近连接、=~/.ssh/config= host 和运行中的容器。

#+begin_src vim
:SimpleRemote
:SimpleRemoteConnect ssh devbox /workspace/project
:SimpleRemoteConnect docker api-dev /workspace/project
:SimpleRemoteTerminal          " 由 SimpleTerminal 统一承载
:SimpleRemoteDisconnect
#+end_src

也可以在 =~/.vimrc.before= 声明常用工作区：

#+begin_src vim
g:simpleremote_profiles = [
  {name: 'dev', kind: 'ssh', target: 'devbox', root: '/srv/app'},
  {name: 'api', kind: 'docker', target: 'api-dev',
    root: '/workspace/api', local_root: '~/src/api'},
]
#+end_src

首次使用某个目标时执行 =:SimpleRemoteInstallAgent=。它会把插件自带的 POSIX shell
agent 原子安装到 =~/.cache/vimrc/simpleremote-agent.sh=；路径可通过
=g:simpleremote_agent= 覆盖。协议仍为 =simpleremote/2=，旧的
=:VimrcRemote*= 命令和 =g:vimrc_remote_*= 变量继续作为兼容接口。

** 工作区映射

连接完成后 SimpleRemote 按以下顺序建立工作区：

- profile 的 =local_root= 或 =g:simpleremote_local_roots= 显式映射；
- Docker 自动选择覆盖远端 root 的最长 bind mount；
- SSH 在本机有 =sshfs= 时创建受管投影；
- 都不可用时降级为 =remote://= virtual workspace。

前三种模式暴露普通本地路径，并把 tab cwd 与 SimpleTree root 切到投影目录，因此
SimpleFinder、SimpleGit、TreeSitter、Minimap、formatter、tags 等依赖本地路径的插件
保持 native 行为。Docker 没有 bind mount、SSH 没有 sshfs 时，不应伪称任意插件都能
透明访问远端文件；virtual 模式保留可靠的异步读写、SimpleCC、远端搜索/Git/terminal、
EditorConfig，并用内置侧栏浏览远端 folder。SimpleTree 改根会同步更新
SimpleRemote workspace，随后新建的 SimpleTerminal 会话也从新 workspace 启动。

#+begin_example
:SimpleRemoteOpen src/main.rs
:SimpleRemoteFind rust
:SimpleRemoteGit status --short
:SimpleRemoteExec cargo test
:SimpleRemoteHealth
#+end_example

完整命令、profile、事件和集成 API 见 =:help simpleremote=。

连接、配置读取和普通 RPC 都有超时（默认 15 秒），可通过
=g:vimrc_remote_request_timeout= 设置毫秒数，设为 0 表示关闭。再次 connect 会先关闭旧
transport，=:VimrcRemoteDisconnect= 也会清理 workspace、配置和挂起请求。不同连接间
不会复用可写状态；旧连接打开且有未保存修改的 buffer 必须先处理，再在新连接中重开。
agent 当前串行处理请求；预计超过 15 秒的 =:VimrcRemoteExec= 应先调高超时，否则本地
请求会超时，而远端命令仍可能占用 transport，需断开后重连。目录列表中的目录项不可
直接打开，可用 =:VimrcRemoteList 子目录= 继续下钻。

这些命令面向受信任的开发环境：workspace root 是默认工作目录而不是文件沙箱，绝对
路径和 =..= 可以访问 workspace 外的路径；=:VimrcRemoteExec= / =:VimrcRemoteGit=
会执行传入的 shell / Git 参数；Docker 进程还可能以容器内 root 身份运行。连接项目也
表示信任其 =simplecc.json= 中的 language-server =command= / =args=，因为它们会在
远端启动。不要连接不受信任的 host、容器或 workspace。

这为 SimpleFinder、SimpleGit、SimpleCC 的 provider 接入提供统一 transport。

第一次打开 =remote://= buffer 时，SimpleCC 会在该 buffer 的上下文中重启 workspace，
把本地 daemon 的 LSP 进程通过同一 SSH 或
Docker transport 启动在远端，并把远端 `file://` URI 映射回 `remote://` buffer。远程
模式目前使用 SimpleCC 的内建语言服务器清单；本地用户配置路径不会错误地传给远端，
远端 workspace 根目录下的 `simplecc.json` 会通过 RPC 读取并传给本地 daemon，项目
自定义 server、args、initializationOptions 和 settings 因此可以生效。断开 remote
会停止这次远程 SimpleCC workspace；回到本地项目后可用 =:SimpleCCStart= 重新启动。
=:VimrcReload= 会先安全断开当前 remote，避免热重载删除仍被 job callback 使用的函数；
若修改了 =remote.vim= controller 本身，请重启 Vim 载入新实现。

*** 原生异步搜索

#+begin_example
:VimrcGrep TODO|FIXME
:VimrcGrep! literal.text
:VimrcGrepWord
:VimrcGrepStop
:VimrcGrepStatus
#+end_example

普通形式使用 ripgrep 正则与 smart-case，=!= 使用字面量。结果以匹配行为单位，
跳转到这一行第一个匹配的字节列；文件名中的空格、冒号及 Unicode 均可处理。
搜索读取磁盘内容，未保存的 buffer 修改需要先保存。搜索不会改变 cwd，完成后保留
编辑焦点，也不会覆盖后来由编译器/LSP 创建的 quickfix 列表。
自动展示跟随发起搜索的窗口所在标签；移动或重编号标签仍能正确识别，
切到其他标签或关闭原窗口后只更新结果，不在当前位置打开面板。

默认尊重 ignore 规则、搜索隐藏文件并排除版本库及 =node_modules/target= 目录；
以 argv 传参，不执行搜索文本中的 shell 字符，也不加载用户的 ripgrep 配置文件。
默认最多 2000 条结果、15 秒；分别用 =g:vimrc_grep_max_results= 和
=g:vimrc_grep_timeout= 调整。=g:vimrc_grep_open=0= 禁止完成后自动打开列表。
另外限制单条 JSON 输出为 1 MiB、总输出为 16 MiB；达到限制会停止并保留已有结果。
非 UTF-8 结果会明确计数并跳过，虚拟远端工作区应使用 SimpleFinder / SimpleRemote。

SimpleFinder 就绪时原有交互式搜索键位继续使用它；插件未就绪时
=<leader>fg/fw/sg/sw= 自动提供以上原生搜索入口。=<leader>sq= 始终可用。

*** 可恢复的大文件模式

默认任一阈值达到时启用：5 MiB、100000 行或单行 20000 字节。可在前置配置中调整：

#+begin_src vim
g:vimrc_large_file_bytes = 5 * 1024 * 1024
g:vimrc_large_file_lines = 100000
g:vimrc_large_file_line_bytes = 20000
#+end_src

字节阈值设为 0 关闭全部自动检测；行数/长行阈值的 0 只关闭该项。长行初读最多
抽查首尾合计 10000 行，未抽到的长行在光标停留时补查；编辑时只检查尺寸、行数
和当前行，不逐键遍历全文。大文件状态触发后保持，防止阈值附近反复启停。

=:VimrcLargeFile= 显示原因、策略和尺寸；=on= 强制开启，=off= 手动关闭，=auto=
恢复自动检测并重新判断。重读文件也会重新判断。SimpleLine 右侧显示 =BIG <size>=。
每个分屏/标签页保存自己的显示设置；退出保护时恢复原值，包括用户原本关闭的
undo/swap，避免把其他窗口或后续普通文件一起降级。Tree-sitter 使用其正式的
buffer 局部禁用标记，不全局停止其他 buffer 的 daemon。

** 代码 buffer 的现代语义键位

有 SimpleCC 的代码文件使用 =F12= 跳转定义、=Shift-F12= 查找引用、
=F2= 重命名；Insert 模式按 =Ctrl-g s= 显示签名，保持插入位置与文本。
=Ctrl-k= 仍保留 Vim 原生 digraph。Visual 模式的 =Space ca/la= 执行选区
代码操作，=Space cf/fm/lf= 格式化选中行；Normal 模式仍格式化全文。
这些键位只安装在当前代码 buffer，包含 SimpleRemote 的 =acwrite= 文件，
尊重已有全局／局部绑定。只读 buffer 保留定义／引用导航和签名帮助；编辑动作只在可写文件
中安装。大文件、无提供者和插件 buffer 不安装，重载或切换文件类型时只清理
配置自己的映射。

=]d= / =[d= 跳转诊断时会展开目的地的折叠，并可用 =Ctrl-O= 返回跳转前位置、
=Ctrl-I= 再次前进。Visual 模式 =p= 使用 Vim 原生保留来源寄存器的粘贴，
支持显式寄存器、行尾、行选区和块选区，仍可一次撤销。

在支持文档卡片的四终端中，SimpleCC 的 hover、签名、诊断和补全文档使用原生
圆角、阴影和细边框，并按 Vim 主题颜色绘制。长文档先在 popup buffer 中换行，
滚动时仍保留原生绘制。Normal 模式有文档弹窗时，=Ctrl-f= / =Ctrl-b= 滚动文档；
没有弹窗时仍是 Vim 原生翻页。插入模式用 =Ctrl-G f= / =Ctrl-G b= 滚动文档，
=Ctrl-G q= 关闭文档；补全菜单的选择、输入位置和撤销历史保持不变。
这些键只在有文档窗口时处理，没有文档时保留原键序列；已有用户映射优先。
=Space lP=（插入模式 =Ctrl-G p=）将当前文档固定到只读真实分屏，保留原始换行、代码语法和当前参数
高亮；可用 =/= 搜索、普通 yank 复制，=:close= 关闭。签名显示当前重载序号，
重复参数、中文和 emoji 的高亮位置随卡片换行保持一致。未知代码语言保留原文。
=Space lq= 关闭 SimpleCC 文档窗口，
不影响交互式符号选择器。已有用户翻页键映射优先。

在 =~/.vimrc.before= 中设置 =g:simplecc_popup_cards = 0= 可保留经典弹窗样式。
普通终端 Vim、旧桥接和复杂交互式窗口继续使用原来的显示与输入方式；
=:VimrcWorkbench= 报告当前文档卡片能力。Markdown 文本沿用 Vim 的语法显示，
不转换为 HTML，也不删除服务器返回的原始标记。

* 按项目启用保存流程

=Space fs=、=:VimrcSave= 和 =<Plug>(VimrcSave)= 使用项目保存策略；未配置时等同
=:update=。普通 =:w= 保持 Vim 的标准写入行为。四终端原生 Save / Ctrl-S 也使用
该入口；原生 Save All / 保存后构建按同一策略逐个保存，只有全部完成后才构建。

#+begin_src vim
let g:vimrc_save_projects = {
      \ '/absolute/project/root': {'rust': {'format': v:true, 'imports': v:true, 'timeout_ms': 3000}},
      \ }
" 或只给当前 buffer 启用：
let b:vimrc_save_pipeline = {'format': v:true, 'imports': v:false}
#+end_src

默认没有任何项目自动启用。项目根来自 =VimrcProjectRoot()=（支持远程项目根），
策略按当前 filetype 精确匹配。流程按格式化→整理 imports→写入顺序运行；每阶段
有超时。Insert / Replace 中请求保存时，保持输入模式和补全菜单，延迟到
=InsertLeave=；继续输入、切换窗口/文件、超时、只读、大文件保护或 LSP 错误都会
停止该次写入，已应用编辑保留供检查，不自动重试。

整理 imports 只接受唯一、当前文件的 edit-only =source.organizeImports=；命令型、
跨文件和资源操作须手工使用 CodeAction。需要新版 SimpleCC daemon，旧 daemon
明确拒绝。远程写入沿用 =BufWriteCmd=，等待 SimpleRemote 的实际 ACK，绑定请求
serial、连接 generation、文档 tick、路径和最终换行；仅 undo 回到 clean 状态不能
冒充保存成功。已有同一快照的 pending write 会被等待，不重复发送；仍在等待、失败
或内容已变化时不开始构建。无 ACK 接口的旧 acwrite 提供者仅保守降级，无法确认
完成时显示 pending。

* 四终端工作台的进一步集成

| 功能 | 操作与行为 |
|------+------------|
| 文档卡片 | =Space lP= / Insert =Ctrl-G p= 固定当前文档到只读分屏；=/= 搜索、普通 yank 复制；=:close= 关闭。当前参数、重载序号与代码语法同步保留。 |
| 关闭与恢复文件 | =Space bd= / =:VimrcCloseBuffer= 保留分屏布局；=Space bR= / =:VimrcReopenBuffer= 恢复最近关闭文件和位置。原生命令面板提供同类命令；未保存或 remote ACK pending 的文件拒绝关闭。历史限于当前 Vim 进程。 |
| 命令面板 | Anvil / Forge / Ember / Frost 均支持 =PageUp= / =PageDown= 按可见结果窗口分页，保持查询焦点；修饰键组合继续交给原快捷键。成功执行的原生命令加入最近使用排序。 |
| 项目保存 | =Space fs=、原生 Save / Ctrl-S 与保存后构建使用上节的 opt-in 策略；普通 =:w= 不自动格式化或整理 imports。 |
| 文件移动与 imports | SimpleTree / SimpleRemoteTree 中 =r= 改名，=x= 剪切后 =p= 移动；支持的运行中语言服务器先返回跨文件修改预览。预览按 =a= 应用，=q= / =Esc= / 关闭预览取消。imports 修改留在 buffer 中供检查和保存，不自动写盘。 |
| 工作台恢复 | 按项目和终端 host 恢复搜索文本、选项、面板可见性、可用尺寸和合理焦点；只在首批真实 Vim metadata 就绪后恢复一次焦点。不会自动启动搜索、构建或保存构建命令、输出及编辑文本。 |

文件移动能力来自语言服务器的 =willRenameFiles= / =didRenameFiles= filters，无需
新增全局开关。旧 backend 或缺少安全远程读取接口时明确提供 Rename only / Cancel，
默认取消；无法安全合并的资源操作、版本化 edits、重叠 edits 或多个服务器同时修改
同一文件会拒绝操作。可查看 SimpleCC 的 =doc/file-rename.md= 了解支持范围。

工作台恢复保存在 XDG state 目录中的数据文件，按项目和 Anvil / Forge / Ember /
Frost 分隔；将环境变量 =JTERM_VIM9_NO_WORKSPACE_STATE= 设为 =1= 可禁用。某面板不可用或
隐藏时焦点回到编辑区；Frost 恢复 Files 焦点只打开 Quick Open 表单，不执行文件操作。
